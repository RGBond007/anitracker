# Governance

AniTracker is currently a maintainer-led open-source project.

## Roles

- **Contributors** report issues, propose changes, improve documentation, and submit pull requests.
- **Maintainers** triage issues, review contributions, make releases, enforce community standards,
  and decide the project's technical direction.

The repository owner is the initial maintainer. Additional maintainers may be invited after a
sustained record of constructive contributions, sound technical judgment, reliable reviews, and
respectful community participation.

## Decisions

Routine changes are decided through issue and pull-request review. Significant changes—including
breaking APIs, schema strategy, major dependencies, security posture, licensing, and project
scope—should be proposed publicly before implementation.

Maintainers aim for consensus and explain consequential decisions. When consensus cannot be
reached, the repository owner has final responsibility for the decision.

## Releases

Maintainers decide when changes are ready to release and follow [RELEASING.md](RELEASING.md).
Security releases may use an abbreviated private process until coordinated disclosure.

## Changes to governance

Governance changes use the same pull-request process as other project changes and should include a
clear rationale. This document can evolve as the contributor and maintainer community grows.
